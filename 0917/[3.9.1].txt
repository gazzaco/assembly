1. 세 가지 서로 다른 명령어 기억 장치(mnemonic)의 예를 제시하시오.
MOV, ADD, SUB

2. 호출 규약(calling convention)이란 무엇이며, 어셈블리어 선언에서 어떻게 사용되는가?
함수가 인자를 전달받고 값을 반환하는 방식을 정의한 규칙, 인자전달순서와 스택정리주체를 결정하는데 사용

3. 프로그램에서 스택 공간을 어떻게 할당(예약)하는가?
스택 포인터 레지스터의 값을 직접 감소시키거나 push명령어를 사용하여 공간 확보

4. '어셈블러 언어(assembler language)'라는 용어가 왜 그다지 정확하지 않은지 설명하시오.
어셈블러는 소스코드를 기계어로 변역해주는 프로그램의 이름이고 언어의 명칭은 어셈블리어이다.

5. 빅 엔디안과 리틀 엔디안의 차이점을 설명하시오. 또한 웹에서 이 용어의 유래를 찾아보시오.
빅엔디안은 최상위바이트를 가장 낮은 메모리 주소에 저장하고 리틀엔디안은 최하위바이트를 가장 낮은 주소에 먼저 저장함.
걸리버여행기에서 달걀의 어느쪽을 깨뜨려 먹어야 하는지로 싸우던 부족 이야기에서 유래

6. 코드에서 정수 리터럴 대신 심볼릭 상수를 사용하는 이유는 무엇인가?
코드의 가독성 높이고, 프로그램 수정 시 특정 값을 한번에 쉽게 변경할수있어서 유지보수가 편리하기 때문

7. 소스 파일은 리스팅 파일과 어떻게 다른가?
소스 파일은 프로그래머가 작성한 원본 코드 파일이고, 리스팅 파일은 어셈블러가 번역을 거쳐 생성한 파일로 기계어(머신 코드), 메모리 오프셋, 심볼 테이블 등이 함께 출력됩니다.

8. 데이터 레이블과 코드 레이블은 어떻게 다른가?
데이터 레이블은 메모리 내 데이터(변수)의 위치를 나타내며, 코드 레이블은 프로그램 실행 흐름의 분기(점프) 지점을 나타내고 일반적으로 콜론(:)으로 끝남

참

10.(참/거짓): 16진수 리터럴은 0x3A로 작성할 수 있다.   
참

11. (참/거짓): 어셈블리어 지시어(directive)는 런타임에 실행된다.   
거짓

12. (참/거짓): 어셈블리어 지시어는 대소문자의 어떤 조합으로든 작성할 수 있다.   
참

13. 어셈블리어 명령어의 네 가지 기본 부품(구성 요소)을 나열하시오.   
레이블, 기억장치, 피연산자, 주석

참

17. 변수에 접근하는 명령어를 작성할 때 숫자 주소를 사용하는 것이 좋지 않은 이유는 무엇인가?   
코드가 추가되거나 수정될 때마다 변수의 물리적 주소가 계속 바뀌므로, 하드코딩된 숫자 주소를 사용하면 유지보수가 불가능

18. ExitProcess 프로시저에는 어떤 유형의 인자를 전달해야 하는가?
프로그램 종료 코드(Return code / Exit code, 예: 정상 종료를 뜻하는 0)인 32비트 정수 인자가 전달되어야 함

19. 프로시저를 끝내는 지시어는 무엇인가?
ENDP

20. 32비트 모드에서 END 지시어에 있는 식별자의 목적은 무엇인가?
프로그램의 시작 진입점(Entry point, 프로그램이 실행을 시작할 주소)을 지정하는 역할을 합니다.

21. PROTO 지시어의 목적은 무엇인가?
외부 함수나 프로시저의 프로토타입(선언부)을 미리 정의하여 컴파일러(어셈블러)에게 알리는 용도로 사용됩니다.
