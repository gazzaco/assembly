## 2. 스택 프레임

### 2.1 스택 프레임의 구성

스택 프레임은 프로시저 실행에 필요한 데이터를 보관하는 영역이다.

일반적으로 다음 항목이 포함된다.

- 전달된 인수
- 복귀 주소
- 이전 프레임의 기준 포인터
- 지역 변수
- 보존할 레지스터

> 모든 프로시저가 위 항목을 반드시 전부 사용하는 것은 아니다.

32비트 환경에서 스택은 일반적으로 **높은 주소에서 낮은 주소 방향으로 성장**한다.

### 2.2 ESP와 EBP

| 레지스터 | 역할 |
|---|---|
| `ESP` | 현재 스택의 최상단을 가리킴 |
| `EBP` | 현재 스택 프레임의 기준 주소로 사용 |

`ESP`는 `PUSH`, `POP`, 지역 변수 할당 등에 따라 변한다.

반면 프레임 설정 후 `EBP`를 유지하면, 매개변수와 지역 변수에 일정한 오프셋으로 접근할 수 있다.

### 2.3 스택 매개변수에 접근하기

다음과 같은 호출을 가정한다.

```c
AddTwo(10, 20);
```

STDCALL에서는 오른쪽 인수부터 스택에 넣는다.

```asm
push 20                 ; 두 번째 인수
push 10                 ; 첫 번째 인수
call AddTwo
```

피호출 프로시저가 다음 코드를 실행하면 프레임 기준점이 설정된다.

```asm
push ebp
mov  ebp, esp
```

이때 스택의 주요 위치는 다음과 같다.

| 주소 | 내용 |
|---|---|
| `[ebp + 12]` | 두 번째 매개변수: 20 |
| `[ebp + 8]` | 첫 번째 매개변수: 10 |
| `[ebp + 4]` | 복귀 주소 |
| `[ebp]` | 호출자의 EBP |

> `[ebp + 8]`이 첫 번째 매개변수라는 규칙은 위와 같은 프레임 설정과 인수 배치를 전제로 한다.

### 2.4 구현 예제

```asm
AddTwo PROC
    push ebp
    mov  ebp, esp

    mov  eax, [ebp + 8]
    add  eax, [ebp + 12]

    pop  ebp
    ret  8
AddTwo ENDP
```

- 두 매개변수의 합을 `EAX`로 반환한다.
- `ret 8`은 복귀 주소를 꺼내 복귀하면서 인수 영역 8바이트도 정리한다.
- `8`은 매개변수의 개수가 아니라 **정리할 바이트 수**이다.

### 2.5 레지스터 매개변수와의 비교

| 구분 | 장점 | 주의점 |
|---|---|---|
| 레지스터 전달 | 스택을 통한 전달을 줄일 수 있음 | 레지스터 수가 제한되고 기존 값 보존이 필요할 수 있음 |
| 스택 전달 | 여러 매개변수를 일정한 구조로 관리 가능 | 인수 배치와 스택 정리가 필요함 |

레지스터 전달도 기존 레지스터 값을 보존하기 위해 `PUSH`와 `POP`을 많이 사용하면 코드가 복잡해질 수 있다.

## 3. 호출 규약

호출 규약은 다음 사항을 정하는 약속이다.

- 인수를 어떤 순서로 전달하는가?
- 반환값을 어디에 저장하는가?
- 누가 인수 영역을 정리하는가?
- 어떤 레지스터를 보존하는가?

### 3.1 C 호출 규약과 STDCALL

| 항목 | C 호출 규약: cdecl | STDCALL |
|---|---|---|
| 스택 인수 전달 순서 | 오른쪽 → 왼쪽 | 오른쪽 → 왼쪽 |
| 인수 영역 정리 | 호출자 | 피호출자 |
| 대표 정리 방식 | 호출 후 `add esp, n` | 피호출자의 `ret n` |
| 가변 인수 함수 | 지원에 적합 | 일반적인 고정 인수 방식은 부적합 |
| 32비트 정수 반환값 | 일반적으로 `EAX` | 일반적으로 `EAX` |

### 3.2 C 호출 규약 예제

```asm
push 20
push 10
call AddTwoC
add  esp, 8             ; 호출자가 인수 영역 정리
```

피호출자는 일반적인 `ret`으로 복귀한다.

```asm
AddTwoC PROC
    push ebp
    mov  ebp, esp

    mov  eax, [ebp + 8]
    add  eax, [ebp + 12]

    pop  ebp
    ret
AddTwoC ENDP
```

### 3.3 STDCALL 예제

```asm
push 20
push 10
call AddTwo             ; 피호출자의 ret 8로 정리
```

> 호출자와 피호출자는 반드시 같은 호출 규약을 사용해야 한다.  
> 양쪽 모두 인수를 정리하거나, 양쪽 모두 정리하지 않으면 스택이 잘못된다.

## 4. 지역 변수와 주소 계산

### 4.1 지역 변수의 특징

지역 변수는 프로시저 실행 중에 사용하는 변수이다.

- 해당 프로시저 내부에서 이름을 관리할 수 있다.
- 호출마다 별도의 저장 공간을 확보할 수 있다.
- 재귀 호출에서 각 호출의 상태를 분리할 수 있다.
- 프로시저가 끝나면 스택 공간을 회수할 수 있다.
- 스택 지역 변수는 자동으로 0으로 초기화되지 않으므로 필요한 초기화 코드를 작성해야 한다.

### 4.2 직접 공간 할당하기

지역 변수는 보통 `EBP`보다 낮은 주소에 배치한다.

```asm
LocalExample PROC
    push ebp
    mov  ebp, esp
    sub  esp, 8                    ; 지역 변수 8바이트 확보

    mov  DWORD PTR [ebp - 4], 10
    mov  DWORD PTR [ebp - 8], 20

    mov  eax, [ebp - 4]
    add  eax, [ebp - 8]

    mov  esp, ebp                  ; 지역 변수 공간 해제
    pop  ebp
    ret
LocalExample ENDP
```

| 위치 | 용도 |
|---|---|
| `[ebp + 8]` 이후 | 스택 매개변수 |
| `[ebp + 4]` | 복귀 주소 |
| `[ebp]` | 저장된 EBP |
| `[ebp - 4]` 이하 | 지역 변수 등 |

> 이 예제처럼 지역 변수 공간을 확보했다면 `pop ebp` 전에 `ESP`를 올바른 위치로 복원해야 한다.

### 4.3 값 전달과 참조 전달

| 구분 | 전달하는 것 | 원본 데이터 변경 |
|---|---|---|
| 값 전달 | 값의 복사본 | 복사본 수정만으로는 원본이 바뀌지 않음 |
| 참조 전달 | 데이터의 주소 | 주소를 역참조하여 원본 변경 가능 |

```asm
push myValue                    ; 값 전달
push OFFSET myValue             ; 주소 전달
```

참조 전달에서는 받은 매개변수가 데이터 자체가 아니라 주소라는 점을 구분해야 한다.

```asm
mov esi, [ebp + 8]              ; 전달받은 주소
mov DWORD PTR [esi], 100        ; 해당 주소의 원본 데이터 수정
```

배열은 모든 원소를 복사하기보다 **시작 주소와 원소 수**를 전달하는 방식이 일반적이다.

### 4.4 LEA와 OFFSET

`LEA`는 메모리 피연산자의 **유효 주소**를 계산한다.

```asm
lea eax, [ebp - 8]              ; 지역 변수의 주소
mov eax, [ebp - 8]              ; 지역 변수의 값
```

| 항목 | `OFFSET` | `LEA` |
|---|---|---|
| 종류 | 어셈블러 연산자 | CPU 명령어 |
| 주요 용도 | 정적 심벌의 오프셋 표현 | 레지스터를 포함한 유효 주소 계산 |
| 스택 지역 변수 주소 계산 | 일반적으로 사용할 수 없음 | 가능 |
| 해당 주소의 데이터 읽기 | 하지 않음 | 하지 않음 |

### 4.5 ENTER와 LEAVE

다음 명령은 지역 변수 공간 8바이트를 가진 스택 프레임을 만든다.

```asm
enter 8, 0
```

이 장에서 사용하는 중첩 수준 `0`에서는 다음 코드에 대응한다.

```asm
push ebp
mov  ebp, esp
sub  esp, 8
```

`LEAVE`는 다음 코드에 대응한다.

```asm
mov esp, ebp
pop ebp
```

사용 예:

```asm
FrameExample PROC
    enter 8, 0

    ; 지역 변수 사용

    leave
    ret
FrameExample ENDP
```

> `LEAVE`는 프레임을 해제하지만, 복귀 자체는 `RET`이 수행한다.  
> 별도로 저장한 일반 레지스터가 있다면 적절한 순서로 복원해야 한다.

### 4.6 LOCAL 지시어

`LOCAL`을 사용하면 이름과 자료형으로 지역 변수를 선언할 수 있다.

```asm
LocalDemo PROC
    LOCAL count:DWORD
    LOCAL buffer[32]:BYTE

    mov count, 0

    ret
LocalDemo ENDP
```

주요 특징:

- 프로시저 본문 명령어보다 앞에 선언한다.
- MASM이 지역 변수의 위치와 스택 공간을 관리한다.
- 배열과 포인터도 선언할 수 있다.
- 선언만으로 초기값이 설정되는 것은 아니다.

```asm
LOCAL temp:DWORD
LOCAL values[10]:DWORD
LOCAL pArray:PTR WORD
```

## 5. Microsoft x64 호출 규약

> 이 절은 Microsoft의 64비트 호출 규약이며, 앞의 32비트 STDCALL과 구분해야 한다.

### 주요 특징

| 항목 | 내용 |
|---|---|
| 첫 번째 정수·포인터 인수 | `RCX` |
| 두 번째 정수·포인터 인수 | `RDX` |
| 세 번째 정수·포인터 인수 | `R8` |
| 네 번째 정수·포인터 인수 | `R9` |
| 추가 인수 | 스택 사용 |
| 64비트 이하 정수 반환값 | 일반적으로 `RAX` |
| Shadow space | 호출자가 최소 32바이트 확보 |
| 스택 정리 | 호출자 책임 |
| 스택 정렬 | 호출 직전 `RSP`를 16바이트 경계에 정렬 |

### 주의할 점

- 정수·포인터 인수에 대한 규칙과 부동소수점 인수 규칙은 구분해야 한다.
- 64비트보다 작은 인수를 전달받았을 때 레지스터 상위 비트가 항상 0이라고 가정하면 안 된다.
- Shadow space는 레지스터 인수를 필요에 따라 저장할 수 있도록 호출자가 제공하는 공간이다.
- Shadow space와 정렬을 위해 필요한 실제 스택 조정량은 현재 프레임 상태에 따라 달라진다.
- 32비트 예제의 `INVOKE` 사용법을 MASM x64에 그대로 적용하지 않는다.

## 6. 재귀

### 6.1 재귀의 개념

재귀 프로시저는 자신을 직접 또는 간접적으로 호출하는 프로시저이다.

재귀에는 두 요소가 필요하다.

1. **종료 조건:** 더 이상 호출하지 않고 결과를 반환하는 조건
2. **재귀 단계:** 문제를 더 작은 문제로 바꾸어 호출하는 과정

종료 조건이 없거나 종료 조건에 도달하지 못하면 스택이 계속 증가한다.

### 6.2 팩토리얼 예제

```c
unsigned factorial(unsigned n) {
    if (n == 0)
        return 1;

    return n * factorial(n - 1);
}
```

32비트 스택 매개변수로 구현한 예제:

```asm
Factorial PROC
    push ebp
    mov  ebp, esp

    mov  eax, [ebp + 8]
    test eax, eax
    jnz  RecursiveCase

    mov  eax, 1
    jmp  Done

RecursiveCase:
    dec  eax
    push eax
    call Factorial

    mov  ecx, [ebp + 8]          ; 현재 호출의 원래 n
    mul  ecx                    ; EDX:EAX = EAX * ECX

Done:
    pop  ebp
    ret  4
Factorial ENDP
```

호출 예:

```asm
push 5
call Factorial                  ; EAX = 120
```

### 6.3 호출과 복귀 과정

`Factorial(3)`은 다음 순서로 호출된다.

```text
Factorial(3)
→ Factorial(2)
→ Factorial(1)
→ Factorial(0)
```

복귀하면서 결과를 계산한다.

```text
Factorial(0) = 1
Factorial(1) = 1 × 1 = 1
Factorial(2) = 2 × 1 = 2
Factorial(3) = 3 × 2 = 6
```

각 호출은 별도의 스택 프레임을 가지므로, 원래의 `n`을 호출별로 유지할 수 있다.

### 6.4 주의사항

- 호출 깊이에 비례하여 스택 사용량이 증가한다.
- 반복문보다 호출·복귀 비용이 커질 수 있다.
- 재귀 호출 후에도 필요한 값을 변경 가능한 레지스터에만 보관하면 안 된다.
- 위 예제는 반환값으로 `EAX`만 사용하므로 결과가 32비트 범위에 들어와야 한다.
- `13!`은 부호 없는 32비트 정수 범위를 초과한다.

## 7. INVOKE, ADDR, PROC, PROTO

MASM의 고수준 프로시저 문법은 인수 전달과 스택 프레임 관리를 간소화한다.

> 아래 설명은 주로 32비트 MASM 기준이다.

### 7.1 역할 비교

| 요소 | 역할 |
|---|---|
| `PROC` | 프로시저 정의 및 매개변수 선언 |
| `PROTO` | 프로시저 원형 선언 |
| `INVOKE` | 인수 전달과 프로시저 호출 |
| `ADDR` | `INVOKE`에서 인수의 주소 전달 |
| `USES` | 지정한 레지스터의 저장·복원 코드 생성 |

### 7.2 PROC: 이름 있는 매개변수

```asm
AddValues PROC,
    first:DWORD,
    second:DWORD

    mov eax, first
    add eax, second
    ret
AddValues ENDP
```

매개변수 이름을 사용하므로 `[ebp + 8]` 같은 오프셋을 직접 작성할 필요가 줄어든다.

STDCALL 설정에서는 MASM이 필요한 프롤로그와 에필로그, 인수 정리 코드를 생성한다.

### 7.3 PROTO: 프로시저 원형

```asm
AddValues PROTO,
    first:DWORD,
    second:DWORD
```

`PROTO`는 다음 정보를 제공한다.

- 프로시저 이름
- 매개변수 개수
- 매개변수 자료형
- 필요한 경우 호출 규약

프로시저 정의보다 먼저 호출하거나, 다른 모듈의 프로시저를 사용할 때 유용하다.

> `PROTO`에는 `USES`와 레지스터 목록을 넣지 않는다.

### 7.4 INVOKE: 인수 전달과 호출

```asm
INVOKE AddValues, 10, 20
```

STDCALL 기준으로 다음과 같은 동작을 표현한다.

```asm
push 20
push 10
call AddValues
```

`INVOKE`보다 앞에 `PROTO` 또는 해당 프로시저의 정의가 있어야 한다.

### 7.5 ADDR: 주소 전달

```asm
INVOKE ProcessValue, ADDR myValue
```

`ADDR`는 정적 변수뿐 아니라 스택 지역 변수의 주소를 전달할 때도 사용할 수 있다.

### 7.6 USES: 레지스터 보존

```asm
ProcessArray PROC USES esi ecx,
    pArray:PTR DWORD,
    count:DWORD

    ; ESI, ECX를 사용하는 처리

    ret
ProcessArray ENDP
```

MASM은 `ESI`, `ECX`를 저장하고 복원하는 코드를 생성한다.

> 반환값이 `EAX`라면 보통 `EAX`를 `USES`에 넣지 않는다.  
> 복귀 직전에 이전 값이 복원되어 계산 결과가 사라질 수 있기 때문이다.

### 7.7 매개변수의 방향

| 분류 | 의미 |
|---|---|
| Input | 처리에 필요한 입력 데이터 |
| Output | 프로시저가 결과를 기록하는 대상 |
| Input-Output | 기존 값을 읽고 수정된 값을 다시 기록하는 대상 |

참조 전달은 Output 또는 Input-Output 구현에 사용하기 좋다.

### 7.8 예제: 두 정수 교환

```asm
SwapValues PROTO,
    pLeft:PTR DWORD,
    pRight:PTR DWORD
```

```asm
SwapValues PROC USES eax edx esi edi,
    pLeft:PTR DWORD,
    pRight:PTR DWORD

    mov esi, pLeft
    mov edi, pRight

    mov eax, [esi]
    mov edx, [edi]

    mov [esi], edx
    mov [edi], eax

    ret
SwapValues ENDP
```

호출:

```asm
INVOKE SwapValues, ADDR value1, ADDR value2
```

두 매개변수는 원래 값을 읽고 새 값을 기록하므로 **Input-Output 매개변수**이다.

### 7.9 타입 검사의 한계

`PROTO`와 `INVOKE`는 다음 오류를 일부 검출한다.

- 인수 개수 불일치
- 일부 인수 크기 불일치

하지만 고수준 언어처럼 완전한 타입 안전성을 제공하지 않는다.

특히 다음은 직접 확인해야 한다.

- 단순 정수를 포인터처럼 전달하지 않았는가?
- 포인터가 올바른 크기의 데이터를 가리키는가?
- 배열 원소 간격을 정확히 계산했는가?

## 8. 다중 모듈 프로그램

### 8.1 개념과 장점

프로그램을 여러 `.asm` 파일로 나누어 독립적으로 어셈블한 뒤, 생성된 `.obj` 파일을 링커로 결합한다.

```text
main.asm   → main.obj
input.asm  → input.obj
calc.asm   → calc.obj
output.asm → output.obj

여러 OBJ 파일 → 링커 → 실행 파일
```

장점:

- 기능별 코드 분리
- 유지보수와 재사용 용이
- 변경된 모듈만 다시 어셈블 가능
- 내부 구현 은닉 및 이름 충돌 방지

### 8.2 관련 지시어

| 지시어 | 역할 |
|---|---|
| `PUBLIC` | 다른 모듈에서 사용할 심벌 공개 |
| `PRIVATE` | 프로시저를 모듈 내부로 제한 |
| `EXTERN` | 다른 모듈에 정의된 심벌 선언 |
| `EXTERNDEF` | 공통 선언으로 정의·참조 모듈을 연결 |
| `INCLUDE` | 공통 선언 파일 포함 |
| `PROTO` | 외부 프로시저의 호출 인터페이스 선언 |

### 8.3 공개 범위 관리

```asm
OPTION PROC:PRIVATE
PUBLIC Calculate
```

- 기본적으로 프로시저를 비공개로 설정한다.
- 외부에서 필요한 프로시저만 공개한다.
- 시작 모듈에 적용한다면 진입 프로시저의 공개 여부도 확인해야 한다.

### 8.4 두 가지 구성 방식

| 방식 | 특징 |
|---|---|
| `EXTERN` + `CALL` | 인수 배치와 호출을 직접 관리 |
| `PROTO` + `INVOKE` | 선언된 매개변수 정보를 활용해 호출 간소화 |

공통 `.inc` 파일에 프로시저 원형을 모아 두면 인터페이스를 일관되게 관리할 수 있다.

```asm
; procedures.inc
ArraySum PROTO,
    pArray:PTR DWORD,
    count:DWORD
```

각 모듈에서 다음과 같이 포함한다.

```asm
INCLUDE procedures.inc
```

> `PROTO` 선언 자체는 실행 명령어가 아니므로 실행 시간 비용을 발생시키지 않는다.

### 8.5 교재 예제의 역할 분리

| 모듈 역할 | 주요 작업 |
|---|---|
| 시작 모듈 | 전체 흐름 제어 |
| 입력 모듈 | 정수를 입력받아 배열에 저장 |
| 계산 모듈 | 배열의 합 계산 |
| 출력 모듈 | 계산 결과 표시 |

## 9. 매개변수 활용 심화

### 9.1 USES와 직접 작성한 프레임의 혼용 주의

다음처럼 `USES`와 수동 프레임 설정을 함께 사용하면 문제가 생길 수 있다.

```asm
Example PROC USES ecx edx
    push ebp
    mov  ebp, esp

    mov eax, [ebp + 8]          ; 예상한 매개변수가 아닐 수 있음

    ; ...
Example ENDP
```

MASM이 삽입한 레지스터 저장 코드가 수동 프롤로그보다 먼저 실행되면 매개변수의 상대 위치가 달라지기 때문이다.

권장 방식:

- 수동 프레임을 사용한다면 레지스터 저장 위치와 복원 순서도 직접 관리한다.
- 고수준 `PROC` 매개변수 문법을 사용한다면 이름 있는 매개변수와 `USES`를 함께 활용한다.
- 자동 생성 코드와 수동 코드를 혼용할 때는 디스어셈블 결과를 확인한다.

### 9.2 8비트·16비트 인수 전달

32비트 스택 매개변수 슬롯을 기대하는 프로시저에는 작은 값을 32비트로 확장하여 전달한다.

부호 없는 값:

```asm
movzx eax, byteValue
push  eax
call  ProcessValue
```

부호 있는 값:

```asm
movsx eax, signedWordValue
push  eax
call  ProcessValue
```

| 명령 | 용도 |
|---|---|
| `MOVZX` | 0 확장 |
| `MOVSX` | 부호 확장 |

주의사항:

- `PUSH`는 8비트 레지스터·메모리 피연산자를 지원하지 않는다.
- 16비트 `PUSH`는 스택을 2바이트만 변경하므로 32비트 슬롯을 기대하는 코드와 맞지 않을 수 있다.
- 인수의 값뿐 아니라 **크기와 순서**도 호출 인터페이스와 일치해야 한다.

### 9.3 32비트 모드에서 64비트 인수 전달

64비트 정수는 두 개의 32비트 값으로 나누어 전달할 수 있다.

**상위 DWORD를 먼저, 하위 DWORD를 나중에 PUSH**한다.

```asm
.data
largeValue QWORD 1122334455667788h

.code
push DWORD PTR [largeValue + 4]  ; 상위 32비트
push DWORD PTR [largeValue]      ; 하위 32비트
call Process64
```

일반적인 프레임 설정 후:

| 주소 | 내용 |
|---|---|
| `[ebp + 8]` | 하위 DWORD |
| `[ebp + 12]` | 상위 DWORD |

이 배치는 낮은 주소에 하위 부분이 놓이는 리틀 엔디언 순서와 일치한다.

### 9.4 작은 지역 변수와 정렬

지역 변수를 선언한 크기의 단순 합과 실제 스택 할당량은 다를 수 있다.

```asm
LOCAL temp:DWORD, flag:BYTE
```

데이터 자체는 5바이트이지만 정렬을 위한 여유 공간 때문에 실제 지역 변수 영역은 더 커질 수 있다.

또한 중첩 호출이나 재귀에서는 현재 활성화된 모든 호출의 지역 변수와 매개변수, 복귀 주소 등을 함께 고려해야 한다.

## 10. Java 바이트코드

### 10.1 JVM의 특징

Java 소스 코드는 바이트코드가 들어 있는 `.class` 파일로 컴파일된다.

JVM은 이 바이트코드를 실행하며, JIT 컴파일을 통해 네이티브 기계어로 변환할 수도 있다.

### 10.2 x86과 JVM 비교

| 구분 | x86 | JVM |
|---|---|---|
| 계산의 주요 피연산자 | 레지스터와 메모리 | 피연산자 스택 |
| 실행 코드 | x86 기계어 | Java 바이트코드 |
| 지역 변수 접근 | 레지스터·주소 등을 활용 | 지역 변수 슬롯의 인덱스 활용 |
| 연산 예 | `add eax, ebx` | `iadd` |

### 10.3 스택 기반 연산 예제

다음 코드를 생각해 보자.

```java
int result = left + right;
```

`left`, `right`, `result`가 각각 지역 변수 슬롯 0, 1, 2에 있다고 가정하면 다음과 같이 표현할 수 있다.

```text
iload_0
iload_1
iadd
istore_2
```

| 명령 | 동작 |
|---|---|
| `iload_0` | 지역 변수 0의 값을 피연산자 스택에 넣음 |
| `iload_1` | 지역 변수 1의 값을 피연산자 스택에 넣음 |
| `iadd` | 두 정수를 꺼내 더한 뒤 결과를 스택에 넣음 |
| `istore_2` | 결과를 꺼내 지역 변수 2에 저장 |

핵심은 **지역 변수 영역과 계산에 사용하는 피연산자 스택을 구분하는 것**이다.

## 11. 디버깅 체크리스트

- [ ] 호출자와 피호출자의 호출 규약이 같은가?
- [ ] 인수를 올바른 순서와 크기로 전달했는가?
- [ ] 값이 필요한 곳에 주소를, 주소가 필요한 곳에 값을 전달하지 않았는가?
- [ ] 지역 변수 사용 전에 필요한 초기화를 했는가?
- [ ] 수동 프레임의 매개변수 오프셋이 실제 코드와 일치하는가?
- [ ] 저장한 레지스터를 올바른 역순으로 복원했는가?
- [ ] 지역 변수 공간을 해제한 뒤 복귀하는가?
- [ ] `ret n`의 `n`이 인수 영역의 바이트 수와 일치하는가?
- [ ] 반환값 레지스터를 불필요하게 복원하지 않는가?
- [ ] 배열 원소 주소 계산에 원소 크기를 반영했는가?
- [ ] 재귀 종료 조건에 도달할 수 있는가?
- [ ] 최대 호출 깊이와 지역 변수 크기를 감당할 스택 공간이 있는가?
- [ ] x64 호출 시 shadow space와 스택 정렬을 만족하는가?

디버거에서는 다음을 확인하면 도움이 된다.

- 호출 전후의 `ESP` 또는 `RSP`
- 프레임 기준점인 `EBP` 또는 `RBP`
- 복귀 주소와 매개변수 위치
- MASM이 생성한 프롤로그·에필로그
- `USES`, `LOCAL`, `INVOKE`가 실제로 생성한 명령어

교재의 `WriteStackFrame` 예제도 스택 프레임 구조를 관찰하는 데 활용할 수 있다.

### 한 문장 정리

**프로시저 호출은 단순한 분기가 아니라, 호출 규약에 따라 인수를 전달하고 실행 상태를 스택에 보관한 뒤 정확히 복원하는 과정이다.**
